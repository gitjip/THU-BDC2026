# 预测诊断经验

本文记录预测结果异常、选股重复和排序行为相关的经验。它和训练策略分开存放，避免后续把“优化器问题”和“预测排序问题”混在一起。

## 1. v1.2.6 与 v1.2.7 观察

`v1.2.6 balanced` 和 `v1.2.7 smooth` 是有效对照：

- 使用同一 commit、同一批 3 个连续 5 交易日窗口；
- 模型规模、窗口、epoch、dropout、weight decay 相同；
- 主要差异是优化器：AdamW 对 Lookahead。

结果显示，Lookahead 只带来很小的外部分数变化：`v1.2.6` 均值约 `-0.029883`，`v1.2.7` 均值约 `-0.029580`。这个差异太小，不能说明 Lookahead 已经解决震荡问题。

更值得关注的是两版 top5 选股高度重复，经常出现 `600010`、`601868`、`600221`、`601288`、`000630`。这说明当前瓶颈可能不是优化器，而是模型排序输出过于固定，或者特征和损失让模型学到了一种稳定但无效的偏好。

## 2. 当前诊断产物

预测仍然只输出提交需要的 top5 文件：

```text
prediction.csv 或 result.csv
```

同时会额外写完整候选排名：

```text
prediction_scores.csv 或 result_scores.csv
```

这个诊断文件包含：

- `rank`：模型排名，1 表示最高；
- `stock_id`：股票代码；
- `pred_score`：模型原始排序分数；
- `selected`：是否进入提交 top5；
- `weight`：进入 top5 时为 `0.2`，否则为 `0.0`。

`*_scores.csv` 不是提交文件，只用于分析模型排序。比赛提交仍然只看 `result.csv`。

从 `v1.3.5` 开始，walk-forward 会在每个历史验证窗口自动补充真实未来收益诊断：

```text
windows/window_*/prediction_diagnostics.csv
windows/window_*/prediction_diagnostics.json
```

其中 `prediction_diagnostics.csv` 是 `prediction_scores.csv` 加上目标窗口真实收益后的明细，重点列包括：

- `target_return`：按评分口径计算的目标窗口未来收益；
- `target_return_rank`：该股票在目标窗口里的真实收益排名；
- `weighted_return`：如果被选中，对最终得分的贡献；
- `stock_prefix`：股票代码前三位，便于粗看市场板块偏好。

窗口级 `prediction_diagnostics.json` 会记录 top5/top20/top50 等高分区的平均真实收益、模型分数和未来收益的 Spearman 相关、真实收益前 5 名被模型排到哪里。

实验目录还会自动生成：

```text
prediction_diagnostics_summary.csv
prediction_repeated_stocks.csv
prediction_diagnostics.json
```

- `prediction_diagnostics_summary.csv`：每个窗口一行，适合横向比较 topK 收益和排序相关性；
- `prediction_repeated_stocks.csv`：统计哪些股票反复出现在 top5/top20/top50，以及这些股票后验收益是否拖分；
- `prediction_diagnostics.json`：实验级概要，会写入 `manifest.json` 和 `experiment_note.md`。

旧实验可以不重训，直接补诊断：

```bash
.venv/bin/python code/src/diagnose_predictions.py experiments/v1.3.4
```

正式最终预测没有未来真实标签，因此只会保留 `final/result_scores.csv`，不会生成带真实收益的诊断。

从 `v1.3.6` 开始，可以比较多个实验的候选池：

```bash
.venv/bin/python code/src/compare_candidate_pools.py experiments/v1.2.13 experiments/v1.3.2
```

默认输出到：

```text
experiments/analysis/candidate_pool_v1.2.13_vs_v1.3.2/
```

重点文件：

- `summary.csv`：每个实验的 topK 后验收益、排序相关性和候选池规模；
- `overlap.csv`：两个实验的 top5/top20/top50 重合度；
- `ensemble_trials.csv`：只用于诊断的简单候选池组合试验；
- `window_metrics.csv`：窗口级原始诊断行。

`ensemble_trials.csv` 中的 `top5_union_equal` 可能超过 5 只股票，不是合法提交策略，只用于判断两个模型的候选池并集是否包含信号。

## 3. v1.2.13 与 v1.3.2 候选池复盘

`v1.2.13 noid` 和 `v1.3.2 noid-rank-replace` 的 12 窗口均值几乎相同：

- `v1.2.13 noid`：top5 均值约 `0.024783`，最差窗口约 `-0.063489`；
- `v1.3.2 noid-rank-replace`：top5 均值约 `0.024755`，最差窗口约 `-0.055007`。

但完整候选池诊断显示二者不是等价模型：

- `noid` 的平均 Spearman 约 `0.033139`，`rank-replace` 约 `-0.020122`；
- `noid` 的 top20 后验收益均值约 `0.018703`，`rank-replace` 约 `0.009320`；
- `noid` 的 top50 后验收益均值约 `0.011429`，`rank-replace` 约 `0.003382`；
- 两者 top5 平均重合度约 `38.3%`，top20 平均重合度约 `47.1%`。

当时结论：`rank-replace` 虽然把最差 top5 窗口略抬高，但 broader ranking 明显弱于 `noid`，所以先作为候选池多样性来源。后续 24 窗口公平复核显示 `rank-replace` 的 top5 均值和最差窗口都优于 noid 与当前集成，因此现在把它作为默认提交单模型。

简单集成也不能直接上：

- top5 并集后验均值约 `0.026125`，略高于两个单模型，但平均候选数约 `8.08`，不是合法提交；
- 平均排名选 top5 均值约 `0.012963`；
- 最小排名选 top5 均值约 `0.009019`；
- top20 Borda 选 top5 均值约 `0.010760`。

这说明候选池并集里有信号，但朴素的二模型重排会把差股票也提前。后续若做集成，应先增加一个可靠的二阶段过滤或风险重排信号，而不是直接平均排名。

## 4. v1.3.7 二阶段风险重排诊断

从 `v1.3.7` 开始，`compare_candidate_pools.py` 会额外评估二阶段过滤/重排信号：

```bash
.venv/bin/python code/src/compare_candidate_pools.py experiments/v1.2.13 experiments/v1.3.2 --output-dir experiments/analysis/stage2_risk_check
```

新增输出：

```text
stage2_rerank_trials.csv
stage2_rerank_windows.csv
stage2_rerank_candidates.csv
```

这些文件仍然是诊断产物，不会改训练、预测或提交文件。风险信号只使用每个窗口 `train_until_as_of` 中已知的历史收盘价计算，不读取目标窗口未来收益。

第一版二阶段候选池只看两个模型各自 top5 的并集，再从并集中选回 5 只股票。已评估的信号包括：

- `volatility_20_rank`：最近 20 个交易日收益波动的横截面分位，越高代表近期越剧烈；
- `overheat_rank`：最近 5 日和 10 日收益较高者的横截面分位，用于刻画短期过热；
- `drawdown_rank`：最近 20 日最大回撤的横截面分位；
- `risk_score`：`0.40 * volatility + 0.35 * overheat + 0.25 * drawdown`；
- `stock_prefix`：股票代码前三位，用于测试简单前缀集中度限制。

基于 `v1.2.13 noid` 与 `v1.3.2 noid-rank-replace` 的 12 窗口结果：

- `low_vol_then_rank_top5` 最好：均值约 `0.030457`，最差窗口约 `-0.032689`，正分窗口 `8/12`；
- 同期 `v1.2.13 noid` top5 均值约 `0.024783`，最差窗口约 `-0.063489`；
- top5 并集均值约 `0.026125`，但平均候选数超过 5，只能作为后验诊断；
- `low_vol_then_rank_top5` 相比并集均值提升约 `0.004332`，`7/12` 个窗口好于并集，平均筛掉并集里约 `37.4%` 的负收益股票；
- 但它仍有窗口会选满负收益股票，不能说明风险过滤已经稳定解决问题。

暂时负面结论更明确：

- 综合 `risk_score` 直接惩罚效果很差，`risk_w1/w2/w3` 均值只有约 `0.0067` 到 `0.0072`；
- `prefix_cap2_*` 前缀集中度限制没有改善均值，说明简单按股票代码前三位限额不够可靠；
- `low_drawdown_then_rank_top5` 和 `low_risk_then_rank_top5` 也弱于 noid。

当前判断：二阶段过滤有希望，但第一版只应保留 `low_vol_then_rank_top5` 作为下一步候选。不要把综合风险惩罚或前缀限制直接接入正式预测。

从 `v1.3.8` 起，`low_vol_then_rank_top5` 已作为可选预测后处理接入：

```bash
BDC_SELECTION_STRATEGY=low_vol_then_rank_top5 BDC_STAGE2_POOL_SIZE=10 sh test.sh
```

walk-forward 中对应 profile 是 `noid-lowvol`。若要只复用已有模型、不重新训练，可运行：

```bash
sh tune.sh v1.3.8 noid-lowvol --windows 12 --skip-final --reuse-models-from v1.2.13
```

注意：这次接入的是“单模型分数前 N 名内低波动优先”，而 `v1.3.7` 诊断的最好结果来自“两模型 top5 并集内低波动优先”。二者相近但不完全等价，必须用 walk-forward 分数确认。

`v1.3.8 noid-lowvol` 已复用 `v1.2.13` 模型跑完 12 窗口，结果不通过效果验收：

- `v1.2.13 noid` 均值约 `0.024783`，最差窗口约 `-0.063489`，正分窗口 `8/12`；
- `v1.3.8 noid-lowvol` 均值约 `0.018015`，最差窗口约 `-0.069905`，正分窗口 `9/12`；
- 低波动后处理 `5/12` 个窗口更好、`7/12` 个窗口更差，平均差值约 `-0.006768`；
- 入选股票平均波动分位从原 top5 的约 `0.710833` 降到约 `0.607778`，说明规则确实在降波动；
- 但被换出的原 top5 股票平均未来收益约 `0.022084`，换入股票平均未来收益约 `0.004604`，说明它经常筛掉的是高波动赢家。

当前判断：单模型 top10 内低波动优先不适合升为默认策略。它可保留为诊断开关，但下一步不应继续单独调低波动阈值；若要继续二阶段方向，应回到“两模型或多模型候选池并集”场景，或改用更能识别上涨质量的信号。

`v1.3.9 ensemble-lowvol` 已验证这个区别：它不训练新模型，默认复用 `v1.2.13 noid` 和 `v1.3.2 noid-rank-replace`，先让两个模型分别给出 top5，再从 top5 并集中按低波动选回 5 只。

12 窗口结果：

- `v1.3.9 ensemble-lowvol` 均值约 `0.030457`，最差窗口约 `-0.032689`，正分窗口 `8/12`；
- `v1.2.13 noid` 均值约 `0.024783`，最差窗口约 `-0.063489`，正分窗口 `8/12`；
- `v1.3.2 noid-rank-replace` 均值约 `0.024755`，最差窗口约 `-0.055007`，正分窗口 `8/12`；
- `v1.3.8 noid-lowvol` 均值约 `0.018015`，最差窗口约 `-0.069905`，正分窗口 `9/12`。

当前判断：`v1.3.9` 基本复现了 `v1.3.7` 诊断中的最好规则，是目前二阶段方向最值得保留的候选。但它仍依赖两个源模型的候选多样性，并没有证明“低波动”本身在单模型 topN 内稳定有效。

## 5. v1.4.1-v1.4.3 18 窗口扩展验证

为检查 `ensemble-lowvol` 是否只适配最近 12 个窗口，补跑了 18 窗口严格对照：

```bash
sh tune.sh v1.4.1 noid --windows 18 --skip-final
sh tune.sh v1.4.2 noid-rank-replace --windows 18 --skip-final
BDC_ENSEMBLE_SOURCES=v1.4.1,v1.4.2 sh tune.sh v1.4.3 ensemble-lowvol --windows 18 --skip-final
```

统一汇总产物位于：

```text
experiments/analysis/validation_v1.4.1_vs_v1.4.2_vs_v1.4.3/
```

18 窗口结果：

- `v1.4.1 noid`：均值约 `0.007921`，最差窗口约 `-0.063489`，正分窗口 `9/18`；
- `v1.4.2 noid-rank-replace`：均值约 `0.020982`，最差窗口约 `-0.055007`，正分窗口 `10/18`；
- `v1.4.3 ensemble-lowvol`：均值约 `0.017967`，最差窗口约 `-0.045579`，正分窗口 `10/18`。

按早期新增 6 窗口和近期 12 窗口拆开看：

- 早期 6 窗口均值：noid 约 `-0.025805`，rank-replace 约 `0.013438`，ensemble 约 `-0.007014`；
- 近期 12 窗口均值：noid 约 `0.024783`，rank-replace 约 `0.024755`，ensemble 约 `0.030457`。

当前判断：

- `ensemble-lowvol` 仍改善了 noid，并且最差窗口最温和，说明低波动并集重排有一定防守价值；
- 但 18 窗口均值低于 `rank-replace`，没有通过“均值高于两个源模型”的验收线；
- 新增早期窗口拖累了 ensemble，说明 12 窗口结论偏乐观，不能只凭 `v1.3.9` 把它视为已证明默认主线；
- 提交前应保留 `rank-replace` 单模型作为默认路径，`single` 原始单模型和 `ensemble` 只作为回退或候选复核。

候选池二阶段诊断也显示，18 窗口下 `low_vol_then_rank_top5` 不再是最强规则：

- `low_vol_then_rank_top5` 均值约 `0.017967`，与实际 `v1.4.3` 一致；
- `low_risk_then_rank_top5` 均值约 `0.018787`，略高于低波动，但仍低于最佳单模型 `v1.4.2`；
- `union_avg_rank_top5` 均值约 `0.016651`，说明简单平均排名仍不足以稳定超过源模型。

因此下一步不应急着扩大集成策略复杂度。更合理的方向是先改源模型信号质量，例如继续做更有假设约束的特征工程，再用 18 窗口以上验证集成是否真正吃到多样性。

`v1.4.4`、`v1.4.5`、`v1.4.6` 使用更新到 `2026-07-27` 的 `stock_data` 补跑了 24 窗口。由于周末没有股票数据，最新可打分窗口是 `2026-07-20 ~ 2026-07-24`，不是包含 `2026-07-27` 的跨周末窗口。

24 窗口结果：

- `v1.4.4 noid`：均值约 `0.002716`，最差窗口约 `-0.127667`，正分窗口 `11/24`；
- `v1.4.5 noid-rank-replace`：均值约 `0.017557`，最差窗口约 `-0.066987`，正分窗口 `14/24`；
- `v1.4.6 ensemble-lowvol`：均值约 `0.014062`，最差窗口约 `-0.069702`，正分窗口 `13/24`。

拆分看：

- 原 18 个可比窗口：noid 约 `0.007921`，rank-replace 约 `0.020982`，ensemble 约 `0.017967`；
- 最近 6 个窗口：noid 约 `0.000496`，rank-replace 约 `0.018557`，ensemble 约 `0.023152`；
- 最新 2 个窗口：noid 约 `-0.092103`，rank-replace 约 `-0.052422`，ensemble 约 `-0.057086`。

当前判断：

- 最新两个窗口整体较难，三条策略都为负，不能用它们证明某个方向已经有效；
- `rank-replace` 在 24 窗口总体最佳，且最新两个窗口也略好于 ensemble；
- `ensemble-lowvol` 最近 6 窗口均值最好，但最新两窗口没有守住 rank-replace，说明它更像防守候选，不是已证明默认主线；
- 若时间有限，下一步优先改源模型特征，而不是继续加复杂集成。

可比性复核后要补充一个限制：`v1.4.4 noid` 使用旧 15 epoch 上限，`v1.4.5 noid-rank-replace` 使用 30 epoch 上限。`v1.4.4` 的所有窗口最佳 epoch 都在 15 以内，但有窗口跑到第 15 轮才结束；`v1.4.5` 有 1 个窗口最佳 epoch 到 16，且有 3 个窗口训练超过 15 轮。因此 `v1.4.5` 相对 `v1.4.4` 的优势不能当作严格公平证明。

从 `v1.4.7` 起，`noid` 主线和正式集成源模型里的 noid 都改为 30 epoch 上限。下一步应先补跑：

```bash
sh tune.sh v1.4.7 noid --windows 24 --skip-final
BDC_ENSEMBLE_SOURCES=v1.4.7,v1.4.5 sh tune.sh v1.4.8 ensemble-lowvol --windows 24 --skip-final
```

补跑后再用 `validate_experiments.py` 汇总。新汇总会生成 `config_comparison.csv`，如果训练预算仍不同，自动在 `readme.md` 里提示。

`v1.4.7` 和 `v1.4.8` 已完成补跑：

- `v1.4.7 noid`：24 窗口均值约 `0.002716`，最差窗口约 `-0.127667`，正分窗口 `11/24`；
- `v1.4.5 noid-rank-replace`：24 窗口均值约 `0.017557`，最差窗口约 `-0.066987`，正分窗口 `14/24`；
- `v1.4.8 ensemble-lowvol`：24 窗口均值约 `0.014062`，最差窗口约 `-0.069702`，正分窗口 `13/24`。

`v1.4.7` 与旧 `v1.4.4` 逐窗口分数完全一致，`v1.4.8` 与旧 `v1.4.6` 也完全一致。这说明旧 noid 的 15 epoch 上限没有实际截断最佳模型；公平预算复核后，`rank-replace` 仍是当前更强的单模型候选。

候选池诊断显示 `v1.4.7` 和 `v1.4.5` 的 top5 平均重合率约 `29.2%`，二者确实提供了多样性。但两模型并集低波动重排均值仍低于 `rank-replace`，说明当前二阶段过滤没有充分利用这种多样性。`rank-replace` 的 broader ranking 也不强：平均 Spearman 约 `-0.0766`，top20/top50 后验收益接近 0 或为负。因此下一步优先提升源模型信号，而不是继续调低波动重排规则。

`v1.4.9 noid-rank-trendq` 对这个方向做了小步特征短测：在 `rank-replace` 上追加 5 个趋势质量特征。最新 3 个目标窗口均值约 `-0.067912`，同日期 `v1.4.5 rank-replace` 约 `-0.019132`，`v1.4.8 ensemble-lowvol` 约 `-0.022241`；逐窗口相对两者都是 `0/3` 胜出。平均 Spearman 约 `-0.2000`，top20 后验收益约 `-0.047259`，没有显示完整排序改善。

复盘文件保存在本地生成目录：

```text
experiments/analysis/review_v1.4.9_trendq_vs_rank_replace/
```

关键观察：

- `trendq` 相对 `rank-replace` 几乎重排了整个 top5：3 个窗口共换入 14 只、换出 14 只，只保留 1 只共同入选股票；
- 换入股票平均真实收益约 `-0.066587`，换出股票平均真实收益约 `-0.014323`，坏在换入池质量；
- `trendq` 的 top20 后验收益也更差，说明不是 top5 权重或偶然抽错，而是高分区整体偏弱；
- 入选前缀从 `rank-replace` 的 `688` 为主（15 次入选里 9 次）变成 `300/600/000/002` 分散，其中 `300` 前缀 6 次；
- `trendq` 入选 top5 平均波动 rank 约 `0.868`，仍是高波动区间；风险分略低于 `rank-replace` 但没有换来更好收益；
- 最新窗口中 `trendq` 选入 `000988`、`600118`、`301308` 这类近期大跌且回撤 rank 很高的股票，像是在押注跌深反弹，但目标窗口继续走弱；
- 三个窗口的最佳内部验证 epoch 都是第 1 轮，后续 train loss 下降但内部验证快速变差，说明这组特征更像让模型更快追噪声。

结论：不扩跑 trendq，下一步应避免继续堆相近的短期动量/波动派生列。不要因为它的风险分略低就认为它更稳，真实 target return 已经否定了这组特征。

## 6. v1.4.5 rank-replace 24 窗口复盘

这轮复盘不再看 `trendq`，而是检查当前默认候选 `v1.4.5 rank-replace` 自己的成功和失败形态。复盘文件保存在本地生成目录：

```text
experiments/analysis/review_v1.4.5_rank_replace_24/
```

总体结论：

- 24 窗口均值约 `0.017557`，中位数约 `0.015113`，最差窗口约 `-0.066987`，正分 `14/24`；
- 最新 3 窗口均值约 `-0.019132`，正分 `1/3`，明显弱于全样本均值；
- top20 后验均值约 `0.000796`，top50 后验均值约 `-0.002242`，说明优势主要集中在最终 top5，不是完整排序稳定有效。

成功/失败窗口的差异主要来自“top5 是否避开坏票”，不是市场整体涨跌：

- score 与入选 top5 中正收益股票数的 Spearman 相关约 `0.890`；
- score 与 top20 后验收益的 Spearman 相关约 `0.828`；
- score 与入选 top5 最差单票收益的 Spearman 相关约 `0.737`；
- score 与市场等权收益的 Spearman 相关只有约 `0.061`；
- score 与平均风险分的 Spearman 相关约 `-0.142`，不能据此做简单风险过滤。

坏窗口共性：

- score < `-0.02` 的 6 个坏窗口中，top20 后验均值约 `-0.037566`，平均 Spearman 约 `-0.267230`；
- 坏窗口入选 top5 平均只有 `0.67/5` 只正收益股票，入选最差单票平均约 `-0.098169`；
- 真实 top5 平均只有 `0.33/5` 只落在模型 top20，说明坏窗口不是 top5 权重分配问题，而是高分区整体没有捕捉到真实强势股票。

前缀和高频股票不能直接做硬规则：

- 入选股票按前缀看，`600` 均值约 `0.033335`，`688` 均值约 `0.017739`，`601` 均值约 `0.015594`，都不差；
- `300` 和 `301` 均值为负，但样本较少，不能直接硬禁；
- 高频股票里既有好票，如 `600026` 9 次入选均值约 `0.068296`、`601872` 6 次入选均值约 `0.060895`，也有弱票，如 `300442`、`301269`、`600893`；
- 因此“前缀集中度限制”或“降低高频股票”容易误伤有效信号。

单模型二阶段后处理也不支持升为默认。对 `v1.4.5` 的 24 窗口离线模拟显示：

- 原始 `model_top5` 均值约 `0.017557`；
- `prefix_cap2_pool10` 均值约 `0.014060`；
- `low_vol_pool10` 均值约 `0.011701`；
- `low_risk_pool10` 均值约 `0.003089`；
- 更大候选池或风险惩罚权重通常继续变差。

当前判断：`rank-replace` 的主要问题是源模型排序信号在某些窗口失效，而不是风险后处理没调好。下一步不要把单模型低波动、低风险、过热惩罚或前缀限制接成默认；更值得做的是改善模型输入信号或训练目标本身。当前对应的小步特征实验是 `v1.6.0 noid-rank-cleanrisk`。

## 7. topK 与现金仓位复盘

比赛提交允许最多 5 只股票，权重和在 0 到 1 之间；评分脚本按 `未来收益率 * 权重` 求和。因此要把两个问题分开看：

- `k`：最终选几只股票；
- `exposure`：总仓位是否用满，未使用权重相当于现金，收益为 0。

“k 越小越激进”只在总仓位仍为 1 时成立。例如 k=1 满仓就是单票 100% 仓位，k=3 满仓就是每只约 33.3%。如果仍然按每只 `0.2` 给权重，那么 k=3 只是总仓位 `0.6`，反而更保守。

基于 `v1.4.5 rank-replace` 24 窗口的离线复盘，产物位于：

```text
experiments/analysis/topk_cash_review/
```

满仓等权结果：

- k=3 均值约 `0.021257`，高于当前 k=5 的 `0.017557`；
- 但 k=3 标准差约 `0.065525`，高于 k=5 的 `0.050324`；
- k=3 最差窗口约 `-0.075930`，差于 k=5 的 `-0.066987`；
- k=3 正分窗口 `13/24`，略低于 k=5 的 `14/24`；
- k=1 最大收益最高，约 `0.203625`，但均值只有 `0.010892`，中位数为负，最差窗口约 `-0.121312`。

固定每股 `0.2` 权重、少选则留现金的结果：

- k=5 均值约 `0.017557`，仍是最好；
- k=3 均值约 `0.012754`；
- k=1 均值约 `0.002178`。

现金仓位方面，简单固定降仓只会线性缩放收益和亏损。在 `v1.4.5` 24 窗口均值为正的前提下，固定不满仓会降低平均分，只能改善最差亏损幅度。

用模型分数做动态是否持股，目前也没有足够证据。top1 分数、top5 分数差、top20 分数差与 top5 未来收益的相关性都很弱；已测试的简单阈值规则都低于“k=5 满仓等权”的均值，最好规则均值约 `0.014772`，仍低于 `0.017557`。

当前判断：

- 默认提交暂不改，仍使用 k=5、总仓位 1.0；
- k=3 满仓可以作为下一轮候选实验，因为它在 24 窗口均值更高，但需要接受更大回撤和更低正分窗口数；
- 不建议默认 k=1，单票满仓过于依赖模型 top1 命中率，而当前 top1 稳定性不足；
- 不建议默认留现金，除非后续找到只用预测时可得信息的可靠置信度信号。

## 8. v1.3.4 rank-lite 诊断结论

`v1.3.4 noid-rank-lite` 的 3 窗口结果显示，问题不是 top5 偶然选错，而是高分区整体排序变差：

- 3 窗口 top20 只有 `26` 只不同股票，比 noid 和 rank-replace 的 `31` 更集中；
- `300408`、`002916`、`300316` 多次进入高分区并拖累收益；
- window_02 中 top5、top20、top50 平均真实收益都为负，说明高分区整体没有信号；
- 真实收益前 5 名经常被模型排到几十名甚至两百名以后。

当前结论：`rank-lite` 没有缓解固定选股池，反而让候选池更窄，不建议扩跑 12 窗口。

## 9. 后续判断方法

优先检查每个 walk-forward 窗口的：

```text
windows/window_*/prediction_scores.csv
windows/window_*/prediction_diagnostics.csv
windows/window_*/prediction.csv
windows/window_*/score.json
```

简单判断：

- 如果多个窗口 top20/top50 高度重复，说明模型偏好过强，继续换优化器大概率收益有限；
- 如果 top5 重复但 top20 有变化，说明可以考虑权重分配、集成或候选重排；
- 如果完整分数差距极小，说明 top5 排名可能非常脆弱，少量噪声就会换股；
- 如果完整分数差距很大但外部分数差，说明模型非常确信但方向错了，应优先改特征或损失函数。

下一步优先用完整排名判断是否存在“固定选股池”。确认后再决定是改特征、改损失，还是做多种子集成。

## 10. 固定选股池的优先嫌疑

早期 39 特征配置默认包含 `instrument`。它是股票代码映射后的整数索引，不是真正的行业、风格或基本面特征。模型把它当连续数值输入时，可能学到“某些编号长期更该被选”的身份偏好。当前默认提交配置已经移除 `instrument`，这里保留的是历史判断依据。

这不一定绝对错误，但在 `v1.2.6` 和 `v1.2.7` 中，多个窗口 top20 高度重复，说明应优先做去编号对照：

```bash
sh tune.sh v1.2.8 noid --skip-final
```

判断重点：

- `summary.csv` 均值和最差窗口是否恶化；
- `prediction_scores.csv` 的 top20/top50 重复度是否下降；
- top5 是否仍集中在同一批股票；
- 如果重复度下降但分数更差，说明身份信息有一定预测贡献，但当前用法可能过强；
- 如果重复度下降且分数不差，后续应默认移除 `instrument`，再考虑行业或板块特征。

`noid` 只是不把 `instrument` 输入模型。股票代码仍用于数据分组、序列构造、打分和输出，不会影响提交文件格式。

## 11. v1.2.8 noid 后续

`v1.2.8 noid` 的多窗口均值改善，说明移除 `instrument` 是值得继续观察的方向。但完整排名也显示，模型更容易选到高波动股票，第二个窗口表现明显拖累均值。

下一步用 `noid-stable` 做低风险对照：

```bash
sh tune.sh v1.2.9 noid-stable --skip-final
```

判断重点不是单看均值，还要看：

- 最差窗口是否改善；
- top20/top50 是否仍有足够变化；
- top5 是否继续集中在高波动股票；
- `prediction_scores.csv` 中入选股票和未入选股票的 `pred_score` 差距是否过大。
